# WORKDAY-SPEC.md — Workday ATS integration (SPEC-ONLY)

**Status:** SPECIFICATION. NO CODE has been shipped for this integration.
Discovery, apply, and follow-up paths for Workday-hosted employers are
NOT yet supported by Fynd. This document exists so the founder can
approve or amend the shape before any implementation begins.

**Rails that MUST hold for any future implementation:**
- Consent-gated everything. `submit_applications` scope required before
  any POST to a Workday form. `process_career_data` required before we
  read a career-site payload.
- No CAPTCHA solving, no scraping of authenticated pages, no headless
  form fill.
- Dry-run by default. Founder-flipped `WORKDAY_LIVE_ENABLED` env flag
  gates real submissions. Preview stays dry-run permanently.
- Follow the same cap / dedup / hard-gate / scope-block invariants the
  Phase 1 Apply Wave already enforces.
- Audit trail: every discovery ingest + every draft submission emits an
  immutable `audit_logs` row in the same shape as
  `wave.authorization_saved` and `outcome.logged`.

---

## §1 · Motivation

A large slice of US employers post via Workday-hosted careers sites
(`myworkdayjobs.com` / `wd*.myworkdayjobs.com`). Every Phase 1
discovery lane skips them today because there's no public JSON feed
per employer — Workday's public surface is the CXS (Career eXperience
Service) API which the vendor documents but rate-limits.

Landing a first-class Workday adapter is expected to unlock 40-70% of
the "SampleCo (demo)" ghost inventory (per founder-side inventory
audit, out of scope for this doc).

## §2 · Discovery model

### 2a · Employer discovery

Per-employer configuration is a small tuple stored in a new collection
`workday_employers`:

```
{
  "id": uuid,
  "employer_key": "acme.com",         # canonical host (same key as supply engine)
  "workday_tenant": "acme",           # first-label subdomain
  "workday_site_id": "External",      # site slug (usually "External" or "Careers")
  "cxs_endpoint": "https://acme.wd5.myworkdayjobs.com/wday/cxs/acme/External/jobs",
  "status": "active" | "paused" | "disabled",
  "added_at": datetime,
  "verified_at": datetime | null,     # founder-attested first-verify
  "notes": str | null,
}
```

Bootstrap for a new employer requires **manual verification** by the
founder — the tuple is not autogenerated. The `POST /employers/connect`
supply-engine surface (Phase 3) collects candidate URLs; a followup
admin tool (out of scope for this doc) converts them into
`workday_employers` rows AFTER human review.

### 2b · Ingest cadence

- **Cold pull** on `workday_employers.added_at` — full page-through of
  the CXS endpoint, page size = 20, honoring the vendor's advertised
  rate limit.
- **Warm pull** — every 6h, delta ingest keyed on
  `jobRequisitionId` + `postedOn`.
- All ingested rows are appended to the existing `jobs` collection
  with `source="workday"`, `discovered_at=now`, honoring the same
  schema Phase 1 gates expect.

### 2c · Ingest rate limits

- Max 1 request / 1.2s per tenant.
- Max 3 concurrent tenants.
- Backoff: 429 → exponential (max 6 retries, capped at 5min).
- If ANY employer's cold pull exceeds a **20-minute wall-clock budget**,
  the pull aborts with a `discovery.workday_budget_exceeded` audit row
  and the employer is `paused` (never disabled — only human review can
  disable).

## §3 · Apply model

### 3a · Draft-only (dry-run) surface

Workday's apply endpoint takes a multi-step JSON payload. The dry-run
adapter must:

1. Fetch the requisition's form spec via CXS `getFormSpec` (public).
2. Build a mapping from the user's canonical profile fields
   (`claims` collection, `resume_versions`, `documents`) into the
   Workday field IDs.
3. Store the built payload verbatim in a new collection
   `workday_apply_drafts` with status `dry_run`. **Do not submit.**
4. Emit an audit row `workday.apply_drafted`.

The draft is what Follow-ups Phase 1 §1d ("preview only, never
auto-sent") already models — the founder's rail applies here without
modification.

### 3b · Live surface (behind `WORKDAY_LIVE_ENABLED=true`)

- Founder-flipped env flag. Default OFF in every environment.
- Even when ON, apply requires:
  - `submit_applications` consent scope granted for the user
  - Fresh wave authorization from the Phase 1 Apply Wave endpoint
    (same `consents_snapshot`, cap, and `hard_gate` invariants apply)
  - User's explicit per-application "Submit" click; no auto-send
- POST to the CXS submit endpoint via the vendor's public interface.
- On 2xx: append `applications` row with `source="workday_live"` and
  a `submission_receipt` row referencing the Workday-returned
  applicationId. NEVER retry a failed submit automatically — surface
  the honest failure state on the tracker.
- On failure: keep the draft; add a `workday.apply_failed` audit row
  with the vendor's error body redacted per the existing
  privacy-export redaction table.

### 3c · Duplicate detection

Workday returns 4xx `duplicate_application` for a re-submit of the
same requisition. The adapter must treat this as a **legitimate success
outcome** (the ledger already reflects the earlier submit) and NEVER
retry.

## §4 · Follow-up model

Follow-up drafts for Workday-submitted applications reuse the Phase 1
`follow_up_drafts` collection unchanged — the source field is the only
Workday-specific addition:

```
{
  ...,
  "source_apply": "workday_live" | "workday_dry_run",
  "workday_application_id": str | null,
}
```

**Manual explicit send only.** No auto-send. Same rail as Phase 1
follow-ups.

---

## §5 · Redaction / privacy

- Never store PII fields from the Workday spec beyond what the user
  has already claimed (`claims` collection).
- Do not persist the Workday session cookies or auth headers beyond the
  request lifetime; they're not necessary for CXS public endpoints and
  MUST NOT be stored.
- The privacy-export bundle (Phase 4 P3) MUST include
  `workday_apply_drafts` and `workday_employers` in the manifest.
- Redaction table extends: `workday_form_spec.data.internal_notes` →
  REDACTED. `workday_apply_drafts.headers` → REDACTED.

---

## §6 · Kill switches

Three independent kill switches, any of which fully halts Workday:

1. `WORKDAY_DISCOVERY_ENABLED=false` — halts ingestion (existing
   `jobs` rows remain queryable).
2. `WORKDAY_LIVE_ENABLED=false` — halts live submissions
   (dry-run drafts still built for tracker visibility).
3. Per-employer `status="paused"` on `workday_employers` — halts
   everything for that one tenant without disturbing others.

The Phase 4 `/standards` measuring-state page will surface all three
switch positions honestly.

---

## §7 · Out of scope (for this spec)

- Auto-generation of `workday_employers` rows from `/employers/connect`
  submissions (this is a human-in-the-loop step; a separate admin-only
  tool will land later).
- CAPTCHA handling. Workday does not present CAPTCHA on CXS public
  endpoints; if a future vendor change introduces one, the discovery
  path halts and surfaces a `workday.captcha_encountered` audit row.
  We do NOT solve CAPTCHA.
- Workday's private "candidate home" surface (post-submit tracker,
  status updates). This is authenticated per-user and would require
  storing user Workday credentials — out of scope permanently.

## §8 · Test plan (spec-only)

When this spec is implemented, the minimum test lock is:

- `test_workday_ingest_cold_page_through` — pages through a mocked CXS
  response, asserts N `jobs` rows written with correct
  `discovered_at` + `source="workday"`.
- `test_workday_ingest_rate_limit_backoff` — 429 response triggers
  exponential backoff, capped at 6 retries.
- `test_workday_draft_dry_run_does_not_submit` — apply endpoint with
  `WORKDAY_LIVE_ENABLED=false` writes a `workday_apply_drafts` row
  and NEVER hits the vendor submit URL (mock httpx transport asserts
  zero apply calls).
- `test_workday_live_requires_wave_auth` — with `WORKDAY_LIVE_ENABLED=
  true`, submit without a fresh wave authorization returns 403.
- `test_workday_duplicate_application_treated_as_success` — 4xx
  duplicate response marks the application state=submitted (not
  failed).
- `test_workday_kill_switches_halt_correctly` — each switch alone
  halts the correct surface without disturbing others.
